## Hop 1: Angular 16 to 17

Target release: 17.3.12. Effort: **M (38 points)**.

### Update command

```sh
ng update @angular/core@17 @angular/cli@17
ng update @angular/material@17
```

### Official update steps: 16 (8 basic, 5 medium, 3 advanced)

#### Basic (every app)

- **v17 node support** (required from 17.0): Make sure that you are using a supported version of node.js before you upgrade your application. Angular v17 supports node.js versions: v18.13.0 and newer
- **v17 ts support** (required from 17.0): Make sure that you are using a supported version of TypeScript before you upgrade your application. Angular v17 supports TypeScript version 5.2 or later.
- **v17 zone.js support** (required from 17.0): Make sure that you are using a supported version of Zone.js before you upgrade your application. Angular v17 supports Zone.js version 0.14.x or later.
- **v17 ng update** (required from 17.0): In the application's project directory, run `ng update @angular/core@17 @angular/cli@17` to update your application to Angular v17.
- **update @angular/material** (required from 17.0, material only): Run `ng update @angular/material@17`.
- **v17 router removals** (required from 17.0): Make sure you configure `setupTestingRouter`, `canceledNavigationResolution`, `paramsInheritanceStrategy`, `titleStrategy`, `urlUpdateStrategy`, `urlHandlingStrategy`, and `malformedUriErrorHandler` in `provideRouter` or `RouterModule.forRoot` since these properties are now not part of the `Router`'s public API
- **v17 switch strictness** (required from 17.0): You may need to adjust the equality check for `NgSwitch` because now it defaults to stricter check with `===` instead of `==`. Angular will log a warning message for the usages where you'd need to provide an adjustment.
- **v17 paramsInheritanceStrategy** (required from 17.0): If you want the child routes of `loadComponent` routes to inherit data from their parent specify the `paramsInheritanceStrategy` to `always`, which in v17 is now set to `emptyOnly`.

#### Medium (apps using these features)

- **v17 style removal** (required from 17.0): Angular now automatically removes styles of destroyed components, which may impact your existing apps in cases you rely on leaked styles. To change this update the value of the `REMOVE_STYLES_ON_COMPONENT_DESTROY` provider to `false`.
- **v17 malformedUriErrorHandler** (required from 17.0): Handle URL parsing errors in the `UrlSerializer.parse` instead of `malformedUriErrorHandler` because it's now part of the public API surface.
- **v17 zone deep imports** (required from 17.0): Change Zone.js deep imports like `zone.js/bundles/zone-testing.js` and `zone.js/dist/zone` to `zone.js` and `zone.js/testing`.
- **v17 AnimationDriver** (required from 17.0): Change references to `AnimationDriver.NOOP` to use `NoopAnimationDriver` because `AnimationDriver.NOOP` is now deprecated.
- **v17 withNoDomReuse** (required from 17.0): To disable hydration use `ngSkipHydration` or remove the `provideClientHydration` call from the provider list since `withNoDomReuse` is no longer part of the public API.

#### Advanced (apps using these APIs)

- **v17 ngDoCheck dynamic components** (required from 17.0): For dynamically instantiated components we now execute `ngDoCheck` during change detection if the component is marked as dirty. You may need to update your tests or logic within `ngDoCheck` for dynamically instantiated components.
- **v17 absolute redirects** (required from 17.0): You may need to adjust your router configuration to prevent infinite redirects after absolute redirects. In v17 we no longer prevent additional redirects after absolute redirects.
- **v17 mutate in signals** (required from 17.0): Use `update` instead of `mutate` in Angular Signals. For example `items.mutate(itemsArray => itemsArray.push(newItem));` will now be `items.update(itemsArray => [itemsArray, …newItem]);`

## Hop 2: Angular 17 to 18

Target release: 18.2.14. Effort: **L (43 points)**.

### Update command

```sh
ng update @angular/core@18 @angular/cli@18
ng update @angular/material@18
```

### Official update steps: 25 (4 basic, 8 medium, 13 advanced)

#### Basic (every app)

- **v18 node support** (required from 18.0): Make sure that you are using a supported version of node.js before you upgrade your application. Angular v18 supports node.js versions: v18.19.0 and newer
- **v18 ng update** (required from 18.0): In the application's project directory, run `ng update @angular/core@18 @angular/cli@18` to update your application to Angular v18.
- **update @angular/material** (required from 18.0, material only): Run `ng update @angular/material@18`.
- **18.0.0 Upgrade TypeScript** (required from 18.0): Update TypeScript to versions 5.4 or newer.

#### Medium (apps using these features)

- **18.0.0. Use \`@angular/core\` StateKey and TransferState** (required from 18.0): Import `StateKey` and `TransferState` from `@angular/core` instead of `@angular/platform-browser`.
- **18.0.0. Opt-in of caching for HTTP requests with auth headers** (required from 18.0): Use `includeRequestsWithAuthHeaders: true` in `withHttpTransferCache` to opt-in of caching for HTTP requests that require authorization.
- **18.0.0.FORCE\_ZONE\_CHANGE\_DETECTION** (required from 18.0): Tests may run additional rounds of change detection to fully reflect test state in the DOM. As a last resort, revert to the old behavior by adding `provideZoneChangeDetection({ignoreChangesOutsideZone: true})` to the TestBed providers.
- **18.0.0: Remove two-way binding expressions in writable bindings** (required from 18.0): Remove expressions that write to properties in templates that use `[(ngModel)]`
- **18.0.0: Move shared providers to the routed component** (required from 18.0): Move any environment providers that should be available to routed components from the component that defines the `RouterOutlet` to the providers of `bootstrapApplication` or the `Route` config.
- **18.0.0. Use absolute URLs** (required from 18.0): Provide an absolute `url` instead of using `useAbsoluteUrl` and `baseUrl` from `PlatformConfig`.
- **18.0.0. Remove \`ServerTransferStateModule\` from app imports** (required from 18.0): Remove all imports of `ServerTransferStateModule` from your application. It is no longer needed.
- **18.0.0: Mark \`OnPush\` views dirty** (required from 18.0): For any components using `OnPush` change detection, ensure they are properly marked dirty to enable host binding updates.

#### Advanced (apps using these APIs)

- **18.0.0: async has been removed, use \`waitForAsync\` instead** (required from 18.0): Replace `async` from `@angular/core` with `waitForAsync`.
- **18.0.0: Deprecated matchesElement method removed from AnimationDriver** (required from 18.0): Remove calls to `matchesElement` because it's now not part of `AnimationDriver`.
- **18.0.0.REMOVE\_OBSOLETE\_IS\_WORKER** (required from 18.0): Update the application to remove `isPlatformWorkerUi` and `isPlatformWorkerApp` since they were part of platform WebWorker which is now not part of Angular.
- **18.0.0: Use zones to track pending requests** (required from 18.0): Remove calls to `Testability` methods `increasePendingRequestCount`, `decreasePendingRequestCount`, and `getPendingRequestCount`. This information is tracked by ZoneJS.
- **18.0.0 Use RedirectCommand or new NavigationBehaviorOptions** (required from 18.0): When a guard returns a `UrlTree` as a redirect, the redirecting navigation will now use `replaceUrl` if the initial navigation was also using the `replaceUrl` option. If you prefer the previous behavior, configure the redirect using the new `NavigationBehaviorOptions` by returning a `RedirectCommand` with the desired options instead of `UrlTree`.
- **18.0.0: Remove deprecated resource cache providers** (required from 18.0): Remove dependencies of `RESOURCE_CACHE_PROVIDER` since it's no longer part of the Angular runtime.
- **18.0.0: Update Node.js URL parsing in \`ServerPlatformLocation\`** (required from 18.0): In `@angular/platform-server` now `pathname` is always suffixed with `/` and the default ports for http: and https: respectively are 80 and 443.
- **18.0.0. Switch from \`platformDynamicServer\` to \`platformServer\`.** (required from 18.0): Replace the usage of `platformDynamicServer` with `platformServer`. Also, add an `import @angular/compiler`.
- **18.0.0. Update \`Route.redirectTo\` to accept functions** (required from 18.0): `Route.redirectTo` can now include a function in addition to a string. Any code which reads `Route` objects directly and expects `redirectTo` to be a string may need to update to account for functions as well.
- **18.0.0: Guards can return \`RedirectCommand\`** (required from 18.0): `Route` guards and resolvers can now return a `RedirectCommand` object in addition to a `UrlTree` and `boolean`. Any code which reads `Route` objects directly and expects only `boolean` or `UrlTree` may need to update to account for `RedirectCommand` as well.
- **18.0.0-Refresh-Newly-Created-Views** (required from 18.0): Be aware that newly created views or views marked for check and reattached during change detection are now guaranteed to be refreshed in that same change detection cycle.
- **18.0.0: \`ComponentFixture.whenStable\` matches \`ApplicationRef.isStable\`** (required from 18.0): After aligning the semantics of `ComponentFixture.whenStable` and `ApplicationRef.isStable`, your tests may wait longer when using `whenStable`.
- **18.0.0. \`ComponentFixture.autoDetect\` behavior more closely matches Application behavior** (required from 18.0): You may experience tests failures if you have tests that rely on change detection execution order when using `ComponentFixture.autoDetect` because it now executes change detection for fixtures within `ApplicationRef.tick`. For example, this will cause test fixture to refresh before any dialogs that it creates whereas this may have been the other way around in the past.

## Hop 3: Angular 18 to 19

Target release: 19.2.25. Effort: **M (38 points)**.

### Update command

```sh
ng update @angular/core@19 @angular/cli@19
ng update @angular/material@19
```

### Official update steps: 18 (6 basic, 6 medium, 6 advanced)

#### Basic (every app)

- **19.0.0\_ng\_update** (required from 19.0): In the application's project directory, run `ng update @angular/core@19 @angular/cli@19` to update your application to Angular v19.
- **update @angular/material** (required from 19.0, material only): Run `ng update @angular/material@19`.
- **19.0.0-standalone-declarations** (required from 19.0): Angular directives, components and pipes are now standalone by default. Specify "standalone: false" for declarations that are currently declared in an NgModule. The Angular CLI will automatically update your code to reflect that.
- **19.0.0-remove-browser-module-with-server-transition** (required from 19.0): Replace usages of `BrowserModule.withServerTransition()` with injection of the `APP_ID` token to set the application `id` instead.
- **19.0.0.2** (required from 19.0): Upgrade to TypeScript version 5.5 or later.
- **19.0.0-router-error-handler** (required from 19.0): Migrate from using `Router.errorHandler` to `withNavigationErrorHandler` from `provideRouter` or `errorHandler` from `RouterModule.forRoot`.

#### Medium (apps using these features)

- **19.0.0-remove-this** (required from 19.0): Remove `this.` prefix when accessing template reference variables. For example, refactor `<div #foo></div>{{ this.foo }}` to `<div #foo></div>{{ foo }}`
- **19.0.0\_localize\_builder\_project\_option** (required from 19.0): In angular.json, replace the "name" option with "project" for the `@angular/localize` builder.
- **19.0.0.1** (required from 19.0): Update tests that relied on the `Promise` timing of effects to use `await whenStable()` or call `.detectChanges()` to trigger effects. For effects triggered during change detection, ensure they don't depend on the application being fully rendered or consider using `afterRenderEffect()`. Tests using faked clocks may need to fast-forward/flush the clock.
- **19.0.0-render-default-fallback** (required from 19.0): When using `createComponent` API and not passing content for the first `ng-content`, provide `document.createTextNode('')` as a `projectableNode` to prevent rendering the default fallback content.
- **19.0.0-update-resolve-interface-return-type** (required from 19.0): Update usages of `Resolve` interface to include `RedirectCommand` in its return type.
- **19.0.0-remove-allow-signal-writes** (required from 19.0): Remove the `allowSignalWrites` option from `effect()` calls. The option is deprecated and no longer required, as signal writes inside effects are allowed by default.

#### Advanced (apps using these APIs)

- **19.0.0-remove-key-value-differs-factories** (required from 19.0): The `factories` property in `KeyValueDiffers` has been removed.
