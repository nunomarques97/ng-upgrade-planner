## Hop 1: Angular 13 to 14

Target release: 14.3.0. Effort: **L (54 points)**.

### Update command

```sh
ng update @angular/core@14 @angular/cli@14
ng update @angular/material@14
```

### Official update steps: 28 (4 basic, 5 medium, 19 advanced)

#### Basic (every app)

- **v14 ng update** (required from 14.0): Run `ng update @angular/core@14 @angular/cli@14` which should bring you to version 14 of Angular.
- **update @angular/material** (required from 14.0, material only): Run `ng update @angular/material@14`.
- **TypeScript 4.6** (required from 14.0): Angular now uses TypeScript 4.6, read more about [any potential breaking changes](https://devblogs.microsoft.com/typescript/announcing-typescript-4-6/).
- **v14 node** (required from 14.0): Make sure you are using [Node 14.15.0 or later](https://www.hostingadvice.com/how-to/update-node-js-latest-version/)

#### Medium (apps using these features)

- **v14 strict forms** (required from 14.0): Form models now require a generic type parameter. For gradual migration you can opt-out using the untyped version of the form model classes.
- **v14 aotSummaries** (required from 14.0): Remove `aotSummaries` from `TestBed` since Angular no longer needs them in Ivy.
- **v14 MatVertical and Horizontal Stepper** (required from 14.0, material only): If you are using `MatVerticalStepper` or `MatHorizontalStepper` make sure you switch to `MatStepper`.
- **v14 JSONP** (required from 14.0): Remove headers from JSONP requests. JSONP does not supports headers and if specified the HTTP module will now throw an error rather than ignoring them.
- **v14 resolvers** (required from 14.0): Resolvers now will take the first emitted value by an observable and after that proceed to navigation to better align with other guards rather than taking the last emitted value.

#### Advanced (apps using these APIs)

- **v14 deprecate protractor entry** (required from 14.0, material only): The deprecated `angular/cdk/testing/protractor` entry point is now removed.
- **v14 chipInput** (required from 14.0, material only): Make sure you specify `chipInput` of `MatChipInputEvent` because it is now required.
- **v14 mixinErrorState** (required from 14.0, material only): You need to implement `stateChanges` class member in abstractions using `mixinErrorState` because the mixin no longer provides it.
- **v14 CdkStepper orientation** (required from 14.0, material only): Use `CdkStepper.orientation` instead of `CdkStepper._orientation`.
- **v14 CdkStepper and MatStepper** (required from 14.0, material only): If you are extending or using `CdkStepper` or `MatStepper` in the constructor you should no longer pass the `_document` parameter since it is now removed.
- **v14 mat-list-item-avatar** (required from 14.0, material only): Rename the `mat-list-item-avatar` CSS class to `mat-list-item-with-avatar`.
- **v14 MatSelectionListChange.option** (required from 14.0, material only): Use `MatSelectionListChange.options` rather than `MatSelectionListChange.option`.
- **v14 getHarnessLoaderForContent** (required from 14.0, material only): Use `getChildLoader(MatListItemSection.CONTENT)` rather than `getHarnessLoaderForContent`.
- **v14 MatSelectionList** (required from 14.0, material only): If you are using `MatSelectionList` make sure you pass `_focusMonitor` in its constructor because it is now required. Additionally, this class no longer has `tabIndex` property and a `tabIndex` constructor parameter.
- **v14 initialNavigation** (required from 14.0): Update `initialNavigation: 'enabled'` to `initialNavigation: 'enabledBlocking'`.
- **v14 Route.pathMatch** (required from 14.0): If you are defining routes with `pathMatch`, you may have to cast it to `Route` or `Routes` explicitly. `Route.pathMatch` is no longer compatible with `string` type.
- **v14 stricter LoadChildrenCallback** (required from 14.0): The promise returned by `LoadChildrenCallback` now has a stricter type parameter `Type<any>|NgModuleFactory<any>` rather than `any`.
- **v14 router scheduling** (required from 14.0): The router does no longer schedule redirect navigation within a `setTimeout`. Make sure your tests do not rely on this behavior.
- **v14 LocationStrategy** (required from 14.0): Implementing the `LocationStrategy` interface now requires definition of `getState()`.
- **v14 http queries** (required from 14.0): Sending `+` as part of a query no longer requires workarounds since `+` no longer sends a space.
- **v14 AnimationDriver.getParentElement** (required from 14.0): Implementing `AnimationDriver` now requires the `getParentElement` method.
- **v14 invalid config** (required from 14.0): Invalid route configurations of lazy-loaded modules will now throw an error rather than being ignored.
- **v14 router resolver** (required from 14.0): Remove the `resolver` from `RouterOutletContract.activateWith` function and the `resolver` from `OutletContext` class since factory resolvers are no longer needed.
- **v14 initialUrl** (required from 14.0): `Router.initialUrl` accepts only `UrlTree` to prevent a misuse of the API by assigning a `string` value.

## Hop 2: Angular 14 to 15

Target release: 15.2.10. Effort: **L (56 points)**.

### Update command

```sh
ng update @angular/core@15 @angular/cli@15
ng update @angular/material@15
```

### Official update steps: 21 (11 basic, 8 medium, 2 advanced)

#### Basic (every app)

- **v15 node support** (required from 15.0): Make sure that you are using a supported version of node.js before you upgrade your application. Angular v15 supports node.js versions: 14.20.x, 16.13.x and 18.10.x. [Read further](https://v15.angular.io/guide/update-to-version-15#v15-bc-01)
- **v15 ts support** (required from 15.0): Make sure that you are using a supported version of TypeScript before you upgrade your application. Angular v15 supports TypeScript version 4.8 or later. [Read further](https://v15.angular.io/guide/update-to-version-15#v15-bc-02)
- **v15 ng update** (required from 15.0): In the application's project directory, run `ng update @angular/core@15 @angular/cli@15` to update your application to Angular v15.
- **V15 update @angular/material** (required from 15.0, material only): Run `ng update @angular/material@15` to update the Material components.
- **v15 no-ivy** (required from 15.0): In your application's `tsconfig.json` file, remove `enableIvy`. In v15, Ivy is the only rendering engine so `enableIvy` is not required.
- **v15 ActivatedRoutSnapshot** (required from 15.0): Make sure that all `ActivatedRouteSnapshot` objects have a `title` property. In v15, the `title` property is a required property of `ActivatedRouteSnapshot`. [Read further](https://v15.angular.io/guide/update-to-version-15#v15-bc-08)
- **v15 relativeLinkResolution** (required from 15.0): In v15, `relativeLinkResolution` is not configurable in the Router. It was used to opt out of an earlier bug fix that is now standard. [Read further](https://v15.angular.io/guide/update-to-version-15#v15-bc-10)
- **v15 TestBed.inject** (required from 15.0): Update instances of `TestBed.inject()` that use an `InjectFlags` parameter to use an `InjectOptions` parameter. The `InjectFlags` parameter of `TestBed.inject()` is deprecated in v15. [Read further](https://v15.angular.io/guide/update-to-version-15#v15-dp-01)
- **v15 providedIn any** (required from 15.0): Using `providedIn: 'any'` for an `@Injectable` or `InjectionToken` is deprecated in v15. [Read further](https://v15.angular.io/guide/update-to-version-15#v15-dp-05)
- **v15 mat refactor** (required from 15.0, material only): In Angular Material v15, many of the components have been refactored to be based on the official Material Design Components for Web (MDC). This change affected the DOM and CSS classes of many components. [Read further](https://rc.material.angular.dev/guide/mdc-migration)
- **v15 visual review** (required from 15.0): After you update your application to v15, visually review your application and its interactions to ensure everything is working as it should.

#### Medium (apps using these features)

- **v15 keyframe** (required from 15.0): In v15, the Angular compiler prefixes `@keyframes` in CSS with the component's scope. This means that any TypeScript code that relies on `keyframes` names no longer works in v15. Update any such instances to: define keyframes programmatically, use global stylesheets, or change the component's view encapsulation. [Read further](https://v15.angular.io/guide/update-to-version-15#v15-bc-03)
- **v15 base-decorators** (required from 15.0): Make sure to use decorators in base classes with child classes that inherit constructors and use dependency injection. Such base classes should be decorated with either `@Injectable` or `@Directive` or the compiler returns an error. [Read further](https://v15.angular.io/guide/update-to-version-15#v15-bc-05)
- **v15 setDisabledState** (required from 15.0): In v15, `setDisabledState` is always called when a `ControlValueAccessor` is attached. To opt-out of this behavior, use `FormsModule.withConfig` or `ReactiveFormsModule.withConfig`. [Read further](https://v15.angular.io/guide/update-to-version-15#v15-bc-06)
- **v15 DATE\_PIPE\_DEFAULT\_OPTIONS** (required from 15.0): Change instances of the `DATE_PIPE_DEFAULT_TIMEZONE` token to use `DATE_PIPE_DEFAULT_OPTIONS` to configure time zones. In v15, the `DATE_PIPE_DEFAULT_TIMEZONE` token is deprecated. [Read further](https://v15.angular.io/guide/update-to-version-15#v15-dp-01)
- **v15 iframe** (required from 15.0): Existing `<iframe>` instances might have security-sensitive attributes applied to them as an attribute or property binding. These security-sensitive attributes can occur in a template or in a directive's host bindings. Such occurrences require an update to ensure compliance with the new and stricter rules about `<iframe>` bindings. For more information, see [the error page](https://v15.angular.io/errors/NG0910).
- **v15 Injector.get** (required from 15.0): Update instances of `Injector.get()` that use an `InjectFlags` parameter to use an `InjectOptions` parameter. The `InjectFlags` parameter of `Injector.get()` is deprecated in v15. [Read further](https://v15.angular.io/guide/update-to-version-15#v15-dp-02)
- **v15 ngModule in providedIn** (required from 15.0): Using `providedIn: ngModule` for an `@Injectable` and `InjectionToken` is deprecated in v15. [Read further](https://v15.angular.io/guide/update-to-version-15#v15-dp-04)
- **v15 RouterLinkWithHref** (required from 15.0): Update instances of the `RouterLinkWithHref`directive to use the `RouterLink` directive. The `RouterLinkWithHref` directive is deprecated in v15. [Read further](https://v15.angular.io/guide/update-to-version-15#v15-dp-06)

#### Advanced (apps using these APIs)

- **v15 canParse** (required from 15.0): Applications that use `canParse` should use `analyze` from `@angular/localize/tools` instead. In v15, the `canParse` method was removed from all translation parsers in `@angular/localize/tools`. [Read further](https://v15.angular.io/guide/update-to-version-15#v15-bc-07)
- **v15 RouterOutlet** (required from 15.0): If your tests with `RouterOutlet` break, make sure they don't depend on the instantiation order of the corresponding component relative to change detection. In v15, `RouterOutlet` instantiates the component after change detection. [Read further](https://v15.angular.io/guide/update-to-version-15#v15-bc-09)
